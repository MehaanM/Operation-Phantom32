# Release Checklist

This checklist must be completed before tagging a Phantom32 release.

---

## Pre-Release

### Code readiness
```
[ ] All features and fixes for this release are merged to main
[ ] CHANGELOG.md is updated with this release's entries
[ ] Version constant (if any) in source reflects the new version
[ ] All 21 CI jobs are green on the release commit
[ ] No FIXME / TODO comments remain for this release scope
```

### Testing
```
[ ] Unit tests pass locally: pio test -e native
[ ] All 13 board builds pass: pio run (all envs)
[ ] Address Sanitizer clean: pio test -e native_asan
[ ] Branch coverage ≥ 70%: pio test -e native_cov (lcov report)
[ ] gitleaks secret scan clean (CI secret-scan job)
[ ] pip-audit reports zero CVEs for CI tooling (dep-scan job)
```

### Hardware validation (required for production release)
```
[ ] Boot and first-boot credential output verified on ESP32-WROOM-32D
[ ] AP WiFi password enforced (device-unique, not "phantom32")
[ ] Dashboard login verified with printed password
[ ] NVS credential persistence verified across reboot
[ ] Credential reset (POST /api/auth/reset-creds) verified
[ ] 24-hour stability test: ESP32-WROOM-32D idle + Beacon Spam active
[ ] 72-hour extended soak: ESP32-WROOM-32D
[ ] PSRAM analytics load verified on ESP32-S3 or WROVER
[ ] Free heap at end of stability test ≥ free heap at start (± 1 KB)
```

### Release artifacts
```
[ ] Firmware .bin files built from exact release commit
[ ] SHA-256 checksums computed for all .bin files
[ ] BUILD_MANIFEST.txt generated by CI (included in artifacts)
[ ] Firmware artifacts attached to GitHub release
```

---

## Tagging

```bash
# Tag the release commit
git tag -a v<VERSION> -m "Release v<VERSION>"
git push origin v<VERSION>
```

Then create the GitHub release:
```bash
gh release create v<VERSION> \
  --title "Phantom32 v<VERSION>" \
  --notes-file RELEASE_NOTES.md \
  firmware/*.bin firmware/*.sha256
```

---

## Post-Release

```
[ ] GitHub release page shows all firmware artifacts
[ ] GitHub release page shows the correct changelog entries
[ ] README.md links or references updated if needed
[ ] Announce in SECURITY.md if this release includes security fixes
[ ] Hardware validation results appended to docs/hardware-validation.md
```

## Firmware Provenance

Each firmware artifact is traceable to its source via `BUILD_MANIFEST.txt`,
which is embedded in the CI artifact for every main-branch build:

```
GIT_COMMIT:    <full 40-char SHA>
GIT_REF:       refs/heads/main (or refs/tags/v<VERSION>)
PIO_VERSION:   6.2.0
RUNNER_OS:     ubuntu-latest
BUILD_TIME:    <ISO 8601 UTC>
WORKFLOW_RUN:  <GitHub Actions run ID>
```

To verify a firmware artifact matches a release:
1. Download the `.bin` from the GitHub release.
2. Compute `sha256sum firmware.bin`.
3. Compare against the `.sha256` file in the release artifacts.
4. Verify the `BUILD_MANIFEST.txt` in the CI run artifacts matches the release tag commit.
